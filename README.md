## 关于 2026-11-04 报告

针对一台 **OrangePi Zero3 / Allwinner H618 / 969 MB RAM** 的边缘设备，回答一个具体问题：

> 这台机器到底能承载什么级别的嵌入式 LLM？

**一句话结论**：它是一台 **10 t/s 级的 350M 推理盒子**，天花板由「969 MB 内存 + 缺 `dotprod` 的 ARMv8.0 + 零 NPU」三者共同锁死。

报告中所有数据均为本机实测，无参数表推算：

| 模型 | 体积 | prefill | 生成 |
|:---|---:|---:|---:|
| LFM2.5-350M Q4_K_M | 216 MiB | 18.4 t/s | **10.4 t/s** |
| Qwen3-0.6B Q4_0 | 359 MiB | 11.4 t/s | **5.87 t/s** |

同时记录了若干可复用的结论：

- **GPU 驱动正常但无计算栈**，且共享内存总线，对 LLM 解码无加速价值
- **H618 无 NPU**（0 TOPS），四重交叉验证
- **内存是真正的天花板**，不是带宽也不是算力；实测经验法则：可用内存 ≥ 模型体积 + 200 MB
- **`/tmp` 是 tmpfs**，模型放这里会双倍占内存
- **Cortex-A53 上线程应设满 4**，2→4 仍有 1.85× 提升（与「小模型带宽受限」的常见假设相反）
